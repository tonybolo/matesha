# Как добавить тему

Тема — это урок «на пальцах», проверка понимания и тренажёр с заданиями, которые создаёт генератор.
Всё, что нужно теме, лежит в **своих** файлах: общий код (загрузчик, главная, тренажёр, проверка ответов) трогать не нужно.

## Файлы темы

| Что | Где |
|---|---|
| Урок и проверочные вопросы | `content/<предмет>8/<id темы>.yaml` (`algebra8`, `geometry8`, `stats8`) |
| Генератор заданий | `tools/generators/t_<имя>.py` (результат: `content/<предмет>8/generated/<id>.json`, руками не править) |
| Картинки урока | `web/src/viz/<Имя>Viz.tsx` (+ `<Имя>Viz.css`) |
| Рисунки к заданиям и вопросам | `web/src/viz/fig/<Имя>Fig.tsx` |
| Навыки (для поиска пробелов) | `content/skills/<файл>.yaml` |
| Шпаргалка | `content/cheatsheet/<файл>.yaml` (вверху `subject: algebra|geometry|stats`) |

## Как объяснять

Заказчик: «на пальцах, чтобы первоклассник понял». В каждом шаге урока по порядку:

1. Живая история или картинка (термометр, долги, ковёр, качели, кубик). Простые слова, короткие абзацы, на «ты».
2. Интерактивная картинка (`viz`): ребёнок крутит числа и сам видит закономерность.
3. Правило в рамке (`note` с `kind: tip`), предупреждение о типичной ошибке (`kind: warn`).
4. Пример, который раскрывается по шагам (`example`).

Новое слово объясняем сразу, до того как им пользоваться. У каждой темы своя картинка, не меньше двух интерактивных.
Шаги со звёздочкой (`⭐` в начале названия) идут в конце и необязательны. 7–8 шагов, 6–7 вопросов проверки.

## YAML темы

```yaml
id: 'geo-01-quadrilaterals'
subject: geometry          # algebra | geometry | stats (для алгебры можно не писать)
order: 1                   # номер темы внутри раздела (0 — тема-повторение)
title: 'Определения четырёхугольников'
summary: 'Строка-две для карточки на главной.'
passScore: 5               # сколько вопросов проверки нужно решить верно
steps:
  - id: s1
    title: 'Что такое четырёхугольник'
    blocks:
      - type: text
        text: >-
          Абзац. Формула в строке: $x^2$. Жирный: **важное**.
      - type: viz
        id: quadParts       # файл QuadPartsViz.tsx
      - type: note
        kind: tip           # tip | warn
        text: 'Правило.'
      - type: math
        tex: 'S=\dfrac{a+b}{2}\cdot h'
      - type: example
        title: 'Условие'
        steps: ['Первая строка решения.', 'Вторая строка.']
check:
  - id: q1
    kind: choice            # выбор из вариантов
    step: 0                 # шаг урока, к которому ведёт «Перечитать»
    prompt: 'Вопрос'
    options: ['Вариант A', 'Вариант B']
    correct: 0
    explain: 'Почему так.'
  - id: q2
    kind: input             # ввод ответа
    step: 1
    prompt: 'Найди угол.'
    answerKind: expr        # expr | roots | compare | order | choice
    answer: '40'
    explain: 'Почему так.'
tasks: []                   # задания создаёт генератор
```

Правила записи формул (их проверяют тесты `web/src/content/content.test.ts`):

- Формулы только внутри `$…$`; вне долларов нет обратных слэшей. В YAML в кавычках `'…'` или `>-` обратный слэш пишется **один раз**: `\dfrac{1}{2}`, не `\\dfrac`.
- Десятичная запятая в TeX: `3{,}5`. Таблицу делает `\begin{array}{c|cc} x & 1 & 2 \cr p & 0{,}5 & 0{,}5 \end{array}` (разделитель строк `\cr`, а не `\\`) или рисунок `fig`.
- Любая команда с обратным слэшем (`\dfrac`, `\cdot`, `\angle`, `\parallel`, `\circ`) должна быть внутри `$…$`.
- Условие задания может содержать `{expr}` — туда подставляется формула из поля `expr` (запись для компьютера: `3/4`, `x^2`, `sqrt(2)`), или готовый TeX из поля `tex`.

- В каждой группе по 24 задания: `build_group` берёт уровни по схеме 1,1,2,1,2,3,2,3 (цель — первые 8). Повторов условия нет: **все числа условия должны быть в тексте `prompt`** (рисунок `fig` в сравнение не входит).
- Поля задания (`task(prompt, answer, kind, hint, solution, skills, **extra)`): `prompt` с формулами в `$…$`; `answer` строкой; `answerKind`: `expr` (число или выражение; дробь `7/2`, десятичная `3,5` тоже принимается, единицы °, см, см² можно не писать), `choice` (`options` — список, `answer` — номер варианта с нуля), `roots` (числа через «;», «нет» — пусто), `compare` (знак), `order`; `reduce=True` — ответ обязан быть несократимой дробью; `hint` — подсказка, не раскрывающая ответ; `solution` — 3–5 строк решения для ребёнка; `skills` — id навыков; `fig={"id": "parallelogram", "props": {...}}` — рисунок над условием; `placeholder` — подсказка в пустом поле.
- Лишние поля для проверки (`geo`, `dist`, `numbers`…) добавлять можно: приложение их игнорирует, а `verify` читает.
- Выбор ответа (`choice`) делаем для вопросов «какая фигура», «верно ли», «какие утверждения верны» (варианты вида «1 и 3»). Варианты не должны выдавать ответ длиной или формой.
- `verify(task)` обязана считать **по-другому**, чем генератор: координаты и векторы, `fractions.Fraction`, SymPy, перебор. Если проверка совпала бы с генератором дословно, она ничего не доказывает.

Запуск (из корня репозитория): `python3 tools/generators/run.py <id темы>`, затем `python3 tools/generators/verify_generated.py` и `python3 tools/verify_answers.py`.

## Картинки урока (`viz`)

`web/src/viz/QuadFamilyViz.tsx` с `export function QuadFamilyViz()` — в YAML это `id: quadFamily` (имя без `Viz`, первая буква маленькая). Принимает необязательный `preset?: string`.

- Корень: `<div className="viz">` и `<div className="viz-title">…</div>`. Готовые классы из `web/src/styles.css`: `viz-step`, `viz-num`, `viz-expr`, `chips`/`chip`/`chip wide`/`on`, `steppers`, `readout`/`readout bad`, `slider`, `slider-label`, `x-row`, `viz-calc`, `viz-actions`, `numline`, `rug` (адаптивный SVG), `grid`, `axis`, `curve`, `good-zone`, `light-row`. Общий `Stepper` («−/+», `web/src/viz/Stepper.tsx`).
- Цвета только из переменных: `var(--accent)`, `--accent-soft`, `--ok`, `--ok-soft`, `--bad`, `--bad-soft`, `--warn-soft`, `--text`, `--muted`, `--line`, `--card`, `--bg`, `--c0`…`--c5` (есть тёмная тема). Свои стили — в `XxxViz.css`, подключать `import './XxxViz.css'`, классы с префиксом картинки (`.qf-…`).
- SVG: `viewBox`, ширина 100%, `role="img"` и `aria-label`, подписи не меньше 11 px, ничего не вылезает за 340 px ширины. Нажимаемое — настоящие `<button>` или большие мишени (не меньше 34 px). Никакого hover.
- Под рисунком **строка-пояснение, которая считается из текущего состояния** (`aria-live="polite"`): что сейчас выбрано, что получилось, почему. Статичная подпись, которая врёт при смене значений, — дефект.
- Для начала даём готовые примеры (чипы-пресеты), чтобы картинка сразу «говорила».

## Рисунок к заданию (`fig`)

`web/src/viz/fig/ParallelogramFig.tsx` с `export function ParallelogramFig(props)` — в задании `fig: {"id": "parallelogram", "props": {"a": 7, "b": 4}}`. Это простой статичный SVG с подписями (вершины A, B, C, D, данные длины и углы); пропорции приблизительные. Значения props: числа, строки, булевы или списки.

## Навыки и шпаргалка

`content/skills/<файл>.yaml`: `id: {title: 'Короткое название навыка', topic: '<id темы>', step: <шаг урока с нуля>}`. Идентификаторы без пересечений с чужими: у геометрии префикс `geo-`, у статистики `st-`, у рациональных чисел `rn-`.
`content/cheatsheet/<файл>.yaml`: `subject: …` и `sections: [{title, items: [{name, tex, lhs?, rhs?}]}]`; у пунктов с `lhs/rhs` тест проверяет равенство числами (запись для компьютера).

## Проверки

```bash
cd web && npx tsc -b && npx vitest run && npm run lint && npm run build
python3 tools/generators/run.py <id> && python3 tools/generators/verify_generated.py && python3 tools/verify_answers.py
```

Потом посмотреть глазами в браузере на экране телефона 390×844 (`npx vite preview --port 41xx`, Playwright, Chromium в `/opt/pw-browsers`): все шаги урока, каждая кнопка картинки, проверка, по одному верному ответу в каждой группе тренажёра, консоль без ошибок.

Сквозной прогон в браузере (все шаги урока, проверка, тренажёр, телефонный экран, светлая и тёмная тема) лежит в `tools/e2e/topic-e2e.mjs`;
как его запускать, написано в шапке файла. Playwright в проект не входит: путь к модулю и к Chromium задаются переменными окружения.
